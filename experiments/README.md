# 🧪 RUXAILAB Eye-Tracker Model Comparison Benchmark

This experiment suite provides a standardized, reproducible benchmark to evaluate and compare the regression algorithms used for eye-gaze calibration in the RUXAILAB eye-tracking API.

It implements the production pipeline style from [app/services/gaze_tracker.py](../app/services/gaze_tracker.py) and hyperparameters from [app/services/config.py](../app/services/config.py). It evaluates 10 model variants across two validation regimes (stratified hold-out and spatial leave-one-point-out cross validation).

## ⚙️ Prerequisites & Setup

1. **Python Environment:**
   Use **Python 3.10** or **3.11** (matching the production container environment in [Dockerfile](../Dockerfile)).
   > [!NOTE]
   > **Python Version Conflict:** The repository's legacy [runtime.txt](../runtime.txt) specifies `python-3.8.8`, whereas [Dockerfile](../Dockerfile) specifies `python:3.11-slim`, and the root [README.md](../README.md) specifies `Python 3x`. Modern dependencies in [requirements.txt](../requirements.txt) (`numpy==2.2.4`, `scikit-learn==1.6.1`, `scipy==1.15.2`) require Python $\ge 3.10$ and will fail to install on Python 3.8.8. Use Python 3.10 or 3.11.

2. **Virtual Environment Setup:**

   **Linux / macOS:**
   ```bash
   python3 -m venv venv
   source venv/bin/activate
   pip install -r requirements.txt
   ```

   **Windows (PowerShell):**
   ```powershell
   python -m venv venv
   venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   ```

3. **Dependencies:**
   The experiment relies on `scikit-learn>=1.6.0`, `pandas>=2.2.0`, and `numpy>=2.0.0` (all included in `requirements.txt`).

## 🚀 Quick Start

### 1. Running with Synthetic Data

If real calibration files are not yet available, generate the standard 9-point calibration dataset:

```bash
# Step 1: Generate synthetic calibration dataset (900 samples across 9 targets)
python experiments/synthetic_data.py --output experiments/data/synthetic_calib.csv

# Step 2: Run the full model benchmark
python experiments/run_experiment.py --data experiments/data/synthetic_calib.csv --feature-set engineered
```
*(Note for Windows: If `python` is not on PATH or opens the Microsoft Store alias, run after activating the virtual environment `venv\Scripts\Activate.ps1`, or use the `py` launcher: `py experiments/run_experiment.py ...`)*

### 2. Swapping in Real Calibration Data

When real user calibration recordings are collected via the frontend client, ensure the CSV contains the following standard schema:

| Column Name | Type | Required by `run_experiment.py` | Description |
| :--- | :--- | :--- | :--- |
| `left_iris_x` | float | **Yes** | Horizontal coordinate of left iris center |
| `left_iris_y` | float | **Yes** | Vertical coordinate of left iris center |
| `right_iris_x` | float | **Yes** | Horizontal coordinate of right iris center |
| `right_iris_y` | float | **Yes** | Vertical coordinate of right iris center |
| `point_x` | float | **Yes** | Screen ground-truth target X coordinate (pixels) |
| `point_y` | float | **Yes** | Screen ground-truth target Y coordinate (pixels) |
| `screen_width` | int | Optional (metadata) | Screen width in pixels (e.g. 1920, generated by `synthetic_data.py`) |
| `screen_height` | int | Optional (metadata) | Screen height in pixels (e.g. 1080, generated by `synthetic_data.py`) |

To run the benchmark on your real recording:

**Linux / macOS (bash):**
```bash
python experiments/run_experiment.py \
  --data path/to/your_real_calibration.csv \
  --feature-set engineered \
  --output-dir experiments/results_real
```

**Windows (PowerShell):**
```powershell
python experiments/run_experiment.py `
  --data path/to/your_real_calibration.csv `
  --feature-set engineered `
  --output-dir experiments/results_real
```

## 📊 Evaluation Metrics & Interpretation

The experiment computes eye-tracking metrics aligned with [app/services/metrics.py](../app/services/metrics.py) and [app/routes/session.py](../app/routes/session.py):

| Metric | Formula / Definition | Target / Good Value | Clinical / Usability Meaning |
| :--- | :--- | :--- | :--- |
| **Mean Euclidean Error (`mean_euclidean_error_px`)** | $\frac{1}{N} \sum \sqrt{(x_i - \hat{x}_i)^2 + (y_i - \hat{y}_i)^2}$ | $\le 40\text{ px}$ (Excellent), $\le 75\text{ px}$ (Good), $\le 120\text{ px}$ (Fair) | Average distance from predicted gaze to the target on screen (thresholds aligned with `app/routes/session.py:L637-L644`). |
| **Median Error (`median_error_px`)** | 50th percentile of Euclidean errors | $< 40\text{ px}$ | Robust error metric less sensitive to blink/tracking outliers. |
| **RMSE (`rmse_px`)** | $\sqrt{\frac{1}{N} \sum (\text{error}_i)^2}$ | $< 60\text{ px}$ | Penalizes large spatial deviations heavily. |
| **Accuracy @ 50px (`accuracy_50px_pct`)** | $\%$ of samples where $\text{error} \le 50\text{ px}$ | $> 70\%$ | Percentage of fixations falling within small UI targets (e.g. buttons). |
| **Accuracy @ 100px (`accuracy_100px_pct`)** | $\%$ of samples where $\text{error} \le 100\text{ px}$ | $> 90\%$ | Percentage of fixations falling within large UI regions (cards, menus). |
| **Precision SD (`precision_xy_px`)** | $\frac{\sigma_{\hat{x}} + \sigma_{\hat{y}}}{2}$ grouped per target | $< 25\text{ px}$ | Gaze jitter / spatial dispersion. Lower values indicate steady fixation. |
| **Training Duration (`train_time_ms`)** | Model fitting wall-clock time in ms | $< 50\text{ ms}$ | Crucial for instant on-device calibration during user onboarding. |
| **Inference Latency (`inference_latency_ms`)** | Single-frame prediction time in ms | $< 2.0\text{ ms}$ | Real-time budget: must remain $< 16\text{ ms}$ for 60 FPS streaming. |

## 🧠 Models Evaluated

1. **Linear Regression:** OLS with `StandardScaler` + polynomial degree 2. Stable baseline.
2. **Ridge Regression:** L2 regularization ($\alpha=0.5$). Fast, controls coefficient growth.
3. **Lasso Regression:** L1 regularization ($\alpha=0.1$). Feature sparsity.
4. **Elastic Net:** Combined L1 and L2 penalty ($\alpha=1.0, l1\_ratio=0.5$). Fast inference.
5. **Bayesian Ridge:** Probabilistic ridge with estimated regularization parameters.
6. **SGD Regressor:** Linear model fitted via stochastic gradient descent with elastic net penalty.
7. **Support Vector Regressor (Linear):** SVR with linear kernel ($C=1.0$). Robust against outliers.
8. **Support Vector Regressor (RBF):** Non-linear kernel ($C=10.0, \gamma=0.1$). Strong generalization on non-linear eye geometry.
9. **Support Vector Regressor (Poly):** Polynomial kernel ($degree=2$).
10. **Random Forest Regressor:** Ensemble of 200 decision trees (`n_estimators=200`, `max_depth=5`, `min_samples_split=5`, `min_samples_leaf=10`). *Note:* The depth limit (`max_depth=5`) and leaf sample threshold (`min_samples_leaf=10`) were explicitly chosen to prevent memorization of the 9 discrete target clusters in calibration feature space (which otherwise collapses training and validation error to an artificial 0.00 px on stratified splits). This regularized setup represents a controlled constraint against cluster lookup behavior rather than an exhaustively tuned score.

## 📁 Understanding the Output Files

When `run_experiment.py` finishes, two primary benchmark files are written to `--output-dir` (default: `experiments/results`):

### 1. `model_comparison_metrics.csv`
A high-level comparison table containing one row per model per validation split:
- **`stratified_80_20`**: Randomly samples 80% of frames per target point for training, testing on the remaining 20%. Demonstrates in-domain calibration performance.
- **`leave_one_point_out`**: 9-fold cross-validation where 8 target dots train the model and the 9th held-out dot tests it. Evaluates spatial extrapolation capability across unexplored screen areas.

### 2. `benchmark_results.json`
Comprehensive machine-readable document containing:
- Run metadata (timestamp, dataset path, feature set, seed).
- Production hyperparameters used for each model.
- Aggregated metrics across both splits.
- `points_detail`: Per-calibration point error breakdowns (`target_x`, `target_y`, sample counts, mean error, precision) for each model, matching the format returned by `/api/session/batch_predict`.

### 3. Diagnostic Audit Reports in `experiments/results/`
Additional diagnostic reports documenting experimental pipeline validation:
- **`sanity_check.md`**: Investigation report documenting the resolution of the LOPO center-collapse artifact and Random Forest cluster memorization.
- **`before_after.md`**: Comparative audit table contrasting model performance before and after applying the diagnostic fixes.
- **`linear_lopo_debug.md`**: Investigation report analyzing linear model LOPO performance, confirming noiseless $0.00\text{ px}$ learnability, geometric gain scaling, and head-shift sensitivity.
